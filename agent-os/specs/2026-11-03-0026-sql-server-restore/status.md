| 5. Agent groundwork | done | **Agent:** one work slot for all work that writes into the guest (`AgentRunner.StartWorkAsync`; work just finishing is waited for 5 s); the slot is reported with every poll (`AgentPollRequest.Busy`), and an update offered while it is held is postponed (logged once). New capability `restore-files-v2`: `FileTransferInfo.IfExists` = replace / keep / fail (unknown values: fail; servers without it still send `Overwrite`). `IRestoreFileSystem.Rename` (target must not exist), `Delete` (regular files only, read-only cleared, never links or folders), `GrantFullControl` (adds an allow ACE by account name or SID; Windows only); all behind the agent-folder guard. **Server:** `AgentRegistry.TryReserveWork` (exclusive per agent; also refused while the agent reports work the server does not know, e.g. after a server restart; a report older than the end of the server's last work there counts as stale), `SetReportedWork` from the poll, no update offer while the agent reports work; file restores into a VM wait for a busy agent with a log line (`Agent:WorkWaitLimit`, 2 h) instead of failing. Transfer sources carry their own volume (`TransferSource`), and `AgentFilePlan.Plan` plans single files from several volumes to given target paths. **Tests:** API test with the real agent (files from D: and L: of a run-time Windows disk into one folder, "fail" keeps an existing file, the slot is reported and a second restore is refused while the first waits at a gate, the slot is free again right after), agent unit test for rename/delete guards. |

in the overlay), `PublishTarget` (ISCSI library on 127.0.0.1, random port, LUN per disk, unit serial `BDFU<id8>-<lun>`, authorization callback), `IPublishHost`, `PublishJournal` (`publish/publishes.json`), `PublishRunner` (fetch, patch, target, attach, find disks by serial, online, mount; MSiSCSI started if needed (and stopped again if it was stopped), the initiator's process id and node name read before the login; login only from 127.0.0.1, owned by the MSiSCSI process (`GetExtendedTcpTable`) with the initiator's node name; `New-IscsiTargetPortal` + `Connect-IscsiTarget -IsPersistent $false`, disk by `SerialNumber`, `Set-Disk` online/writable, MBR drive letters removed, `Add-PartitionAccessPath` by partition offset; unmount with `DeleteVolumeMountPointW` (a dangling mount point is removed as a folder); detach starts MSiSCSI if needed (portals are only visible while it runs), takes the session's disks offline first (a disk in use cannot be logged out), `Disconnect-IscsiTarget`, `iscsicli RemoveTargetPortal`, checks that session and portal are gone, and stops MSiSCSI again if a publish started it (marker file, so also after an agent crash). The VM was left clean (no portals, sessions, disks or folders; MSiSCSI stopped/Manual). **Lab-only:** throughput over the real HTTPS channel, the agent as Local System, Server 2012 R2 (net48). |
